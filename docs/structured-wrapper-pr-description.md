# Add opt-in formula expressions inside registered wrappers

Registered formula wrappers can retain an inner coordinate expression or coefficient design instead of treating `1+x` as elementwise arithmetic. The function-call interface uses `by=` grouping, including scalar/composite groups and standard nesting expansion. Structured inner group terms and a second positional grouping argument are unsupported; ordinary `(1 + x | group)` terms retain their existing semantics. Registration is explicit and local to `model_description` or `design_matrices`.

The change adds a list AST node and lazy call lists, structured metadata with fitted design evaluation, and variable discovery for quoted grouping columns. It preserves ordinary formula and namespace behavior. Declared categorical domains may include unobserved levels; incomplete declarations and duplicates are rejected.

The paired Bambi feature consumes this interface. A Formulae release containing this change is required before Bambi's release dependency minimum can be set. No covariance functions or inference algorithms are implemented here.

Validation commands and current results are recorded in the paired Bambi development validation report. The 179 focused parser/resolver/design/new-data regressions pass for the narrowed API. The full Formulae suite is configured in the paired Bambi PR workflow against the exact Formulae feature commit; the prior feature commit passed 288 tests and one skipped on Python 3.11–3.14. The revised commit reruns that matrix; its results remain pending. Independent review identified and prompted regression coverage for canonical-name collisions, outer interactions, and grouping subset expressions.

The tandem interface remains necessary after removing structured bar syntax: the resolver must retain formula coefficient semantics, scalar/composite/nested grouping, canonical identity and variable discovery; lists need AST/lazy-call support; fitted structured designs need metadata and new-data evaluation. Categorical declarations retain required unobserved coefficient levels, and matching quote delimiters preserve quoted column names. These changes are independent of structured bars. No Bambi-specific parser or probability code is added.

Independent review also found canonical-name collisions between a backquoted predictor and a multi-term design, and between quoted grouping columns named True/False/None and Python literals. Structured canonical names now preserve quoted variables and arithmetic grouping; focused design/round-trip tests cover both fixes. Ordinary call rendering and evaluation remain unchanged.
